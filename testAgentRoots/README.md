# Как повторить эксперименты

Agent root — рабочая папка отдельного варианта эксперимента. В ней находятся `benchmark_config.toml`, локальная конфигурация Codex и относительные symlink на нужные скиллы.

## Подготовка

Нужны macOS/Linux, Bash, Python 3.11+, авторизованный Codex CLI в `PATH`, а для Jira-вариантов — доступ к тестовой задаче. CLI-варианты используют настроенный [jira-cli](https://github.com/ankitpokhrel/jira-cli); workflow-скрипты также требуют `jq`. Для опубликованных GitLab-скиллов используется [glab](https://docs.gitlab.com/cli/).

- Проект должен быть доверенным в Codex для загрузки локальных конфигураций. Модель, провайдер и авторизация наследуются от глобальных настроек; используйте одинаковые настройки для сравниваемых вариантов.
- В глобальном конфиге определите собственный `mcp_servers.jira` с подключением и авторизацией, отключённый по умолчанию (`enabled = false`). MCP-варианты включают его локально. Нужен сервер с инструментами `jira-jira_get_issue`, `jira-jira_transition_issue` и `jira-jira_update_issue`; для полного каталога глобальные фильтры инструментов должны отсутствовать.
- Отключите остальные пользовательские MCP и исключите посторонние пользовательские скиллы из окружения эксперимента. Системные скиллы и общие инструкции должны быть одинаковыми для всех вариантов.
- Все roots используют `service_tier = "default"`, `approval_policy = "never"`, `sandbox_mode = "workspace-write"` и сетевой доступ внутри песочницы. Операции за пределами разрешений завершаются без интерактивного запроса. В `3_mcp` операции workflow разрешены через локальные `approval_mode = "approve"`.
- В примерах сохранён ключ `RC-80899`. Для своей задачи замените его в `prompt`, `cleanup_args` и `validation_args` соответствующих `benchmark_config.toml`. Для workflow должны быть доступны переходы в `New` и `Development` и редактирование меток.

## Варианты

Сравнивайте roots с одинаковой первой цифрой: 1 — ответ `hello`, 2 — чтение заголовка и описания Jira-задачи, 3 — перевод в `Development`, добавление `ai_agent` и чтение описания.

| Root | Инструменты |
|---|---|
| `1_empty` | Без локального скилла и Jira MCP |
| `1_cli` | jira-task-read |
| `1_mcp` | Полный каталог Jira MCP |
| `2_cli` | jira-task-read |
| `2_mcp` | Полный каталог Jira MCP |
| `2_mcp_concise` | Только jira-jira_get_issue |
| `3_cli` | jira-start-task-cli со скриптом |
| `3_cli_common` | jira-start-task-cli-direct |
| `3_cli_common_detailed` | jira-cli-direct-detailed |
| `3_mcp` | jira-start-task-mcp и Jira MCP |

Скиллы подключены относительными ссылками из `.agents/skills/` каждого root на [skills/](../skills/) или [experimental-skills/](../experimental-skills/). Переносите репозиторий целиком с сохранением symlink.

## Запуск

Один вариант, пять повторов (из корня репозитория):

```bash
cd testAgentRoots/1_cli
bash ../run_benchmark.sh 5
```

Все десять вариантов, по пять повторов (из корня репозитория):

```bash
bash testAgentRoots/run_all_benchmarks.sh 5
```

Без аргумента выполняется один повтор. Общий скрипт последовательно запускает варианты из их рабочих папок и останавливается при первой ошибке. Число повторов — единственный позиционный аргумент; остальные параметры задаются в TOML.

`run_benchmark.sh` загружает необязательный `testAgentRoots/.env` в синтаксисе Bash, экспортируя переменные поверх текущего окружения. Файл не включён в репозиторий. Прямой вызов `python3 ../../benchmark/benchmark.py 5` из root не загружает `.env`.

## Состояние задачи и результаты

Варианты `3*` изменяют Jira-задачу: переводят в `Development` и добавляют `ai_agent`. Проверка выполняется до cleanup. Перед серией и после каждого повтора cleanup устанавливает `New` и удаляет `ai_agent`, сохраняя остальные метки. Это фиксированное исходное состояние; прежний произвольный статус не восстанавливается, история Jira сохраняется.

Результаты создаются в `benchmark/results/` отдельно для каждой серии: `summary.json`, `summary.csv`, метрики и логи повторов. Каталог исключён из Git; готовые результаты не публикуются.

Параметры, метрики, validation и cleanup описаны в [README бенчмарка](../benchmark/README.md).
